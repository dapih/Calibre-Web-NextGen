# Windows native packaging and release research

Date: 2026-11-04. For [Compare offline Windows packaging and release options](https://github.com/dapih/Calibre-Web-NextGen/issues/3), against repository commit [`f342724`](https://github.com/dapih/Calibre-Web-NextGen/tree/f342724c25e82bbca580c04786154e0dd71c4811). **Recommendations remain provisional; no packaging architecture has been selected.** This work did not install dependencies, change application code, build/sign executables, or publish releases.

## Finding and baseline

The agreed target is Windows 11 x64, browser UI plus tray application, and one offline setup EXE. Python, packages, native tools and configurations must be private to CWNG, with no global Python/package changes or persistent PATH changes. Required workflows remain library/reader/ingest/conversion/local metadata/OPDS/Kobo/KOReader. Remote metadata providers still require Internet access; device sync needs the relevant LAN connection.

**Provisional preference:** prototype a private installed CPython/package tree with separate native-tool directories, delivered by **Inno Setup**. Evaluate official embeddable CPython first, with pinned python-build-standalone (PBS) as its alternative; compare PyInstaller one-directory if useful. One installer EXE can install many private files. A one-file frozen runtime instead adds launch-time extraction and temporary-directory behavior. This preference is engineering judgment, not compatibility evidence. [Python embedding](https://docs.python.org/3.13/using/windows.html#the-embeddable-package), [PyInstaller operation](https://pyinstaller.org/en/stable/operating-mode.html).

The pinned [Dockerfile](https://github.com/dapih/Calibre-Web-NextGen/blob/f342724c25e82bbca580c04786154e0dd71c4811/Dockerfile) uses Python **3.13.14**, PBS **20260623**, Calibre **9.11.0**, kepubify **v4.0.4**, ImageMagick, Ghostscript, libmagic and archive tools. Its Linux binaries/s6 services/paths cannot become a Windows payload directly. Apt packages and the UnRAR image are not fully pinned. The [Python dependency ranges](https://github.com/dapih/Calibre-Web-NextGen/blob/f342724c25e82bbca580c04786154e0dd71c4811/pyproject.toml) also need a Windows lock and binary inventory. Allowed faust-cchardet **2.1.18–2.1.19** has no cp313 Windows x64 wheel in its release metadata: choose a verified build-time wheel build, reviewed dependency change, or supported interpreter graph later. Users must never need a compiler/pip. LDAP dependencies are already excluded on Windows. [Release files 2.1.18](https://pypi.org/pypi/faust-cchardet/2.1.18/json), [2.1.19](https://pypi.org/pypi/faust-cchardet/2.1.19/json).

## Runtime comparison

| Candidate | Evidence and tradeoffs |
| --- | --- |
| Official CPython embeddable ZIP | Designed for embedding. `._pth` constrains module paths and ignores environment/registry paths; `site` is disabled unless enabled. Vendor packages at build time: pip and Tcl/Tk are absent and regular pip-managed installation is unsupported. Verify package metadata/`.pth` needs and every helper process. Exact embeddable version/artifact availability is still a gate. [Embedding](https://docs.python.org/3.13/using/windows.html#the-embeddable-package), [path controls](https://docs.python.org/3.13/library/sys_path_init.html#pth-files). |
| Private PBS CPython | The pinned release contains `cpython-3.13.14+20260623-x86_64-pc-windows-msvc-install_only.tar.gz`, separately from free-threaded builds. A private interpreter can run Python helpers without freezing each entry point. Relocatability is not isolation: prove explicit module paths and isolated initialization; no user-side uv/download/bootstrap. [Release API](https://api.github.com/repos/astral-sh/python-build-standalone/releases/tags/20260623), [distribution guide](https://github.com/astral-sh/python-build-standalone/blob/main/docs/running.md), [isolated PyConfig](https://docs.python.org/3.13/c-api/init_config.html#isolated-configuration). |
| PyInstaller one-directory / one-file | Includes Python; Windows output must be built for the intended OS/interpreter/architecture. Dynamic imports/assets/helper entry points need spec/hooks. `sys.executable` is the frozen program, not a general interpreter. Its bootloader changes DLL search with `SetDllDirectoryW`, affecting children. One-file also extracts at launch. Prefer one-directory for comparison because the installer already provides one download. [Operation](https://pyinstaller.org/en/stable/operating-mode.html), [runtime](https://pyinstaller.org/en/stable/runtime-information.html), [subprocess caveats](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application). |

A venv alone does not demonstrate DLL/tool isolation. Windows resolves dependent DLLs by name even when an initial DLL has an absolute path. Keep CWNG Python, Calibre's Python/Qt, and ImageMagick dependencies separate rather than flattening DLLs. [Windows loader](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order).

## Installer and tray comparison

| Candidate | Fit and cost/ownership constraints |
| --- | --- |
| **Inno Setup** | Single EXE, per-user non-admin option, uninstall, Restart Manager and integrated signing. Stable `AppId` supports upgrade identity; lifecycle/migrations still need design. Best provisional desktop fit. [Features](https://jrsoftware.org/isinfo.php), [privileges](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm), [AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm). Its [license](https://github.com/jrsoftware/issrc/blob/main/license.txt) permits commercial use with conditions; the current [FAQ](https://jrsoftware.org/isorder.php) requests qualifying commercial users purchase a license but says payment is not strictly required. |
| **NSIS** | Credible scriptable installer/uninstaller with `RequestExecutionLevel user`. More application lifecycle logic is custom script/plugin work. Review recursive cleanup and plugin provenance. Core and compression modules have different licenses. [Reference](https://nsis.sourceforge.io/Docs/Chapter4.html), [license texts](https://nsis.sourceforge.io/License). |
| **WiX MSI + Burn EXE** | Attached payloads support offline bundles; MSI provides upgrade/service primitives. More authoring, worthwhile if enterprise MSI deployment/repair matters. Rollback depends on upgrade scheduling. [Bundle](https://docs.firegiant.com/wix/schema/wxs/bundle/), [MajorUpgrade](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/), [services](https://docs.firegiant.com/wix/schema/wxs/serviceinstall/). Review [MS-RL](https://github.com/wixtoolset/wix/blob/main/LICENSE.TXT) and current [maintenance fee/EULA](https://docs.firegiant.com/wix/osmf/), including its stated $10,000 annual-revenue threshold. |

The tray belongs in the signed-in user's application process. An installer/runtime does not create its lifecycle automatically. A Windows service cannot directly display the tray; headless/pre-login service mode would need a separate session process, IPC and account/data policy and is outside the chosen tray-desktop scope. Optional login startup remains a decision. [Notification area](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area), [service restrictions](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services).

## Isolation acceptance criteria

These are proposed prototype gates, not verified current behavior:

1. Record executable, prefixes, `sys.path`, imported module and loaded DLL origins for the server and every helper. Third-party imports must come from CWNG; host `PYTHONHOME`/`PYTHONPATH`, registry/user-site/CWD must not redirect them. Windows system DLLs remain OS dependencies. [Python controls](https://docs.python.org/3.13/library/sys_path_init.html#pth-files).
2. Install/run/upgrade/uninstall must leave host Python, Calibre, ImageMagick, package stores, associations and persistent user/machine PATH unchanged.
3. Restrict DLL directories before imports, including ctypes/extensions. Launch absolute tool paths with argument lists, controlled CWD and sanitized per-child environment/PATH; inspect grandchildren. PyInstaller's inherited loader state needs a demonstrated process boundary/reset strategy, not environment sanitization alone. [DLL security](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-security), [Python DLL directories](https://docs.python.org/3.13/library/os.html#os.add_dll_directory), [PyInstaller inheritance](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application).
4. Give every Calibre child app-owned configuration/cache/temp paths and no inherited desktop plugins. Explicitly control ImageMagick configuration/delegates, Ghostscript and Qt overrides, libmagic DLL/database and archive backend paths. Environment changes stay process-local. [Calibre variables](https://manual.calibre-ebook.com/customize.html#environment-variables), [Wand linking](https://docs.wand-py.org/en/latest/guide/install.html#explicitly-link-to-specific-imagemagick), [ImageMagick resources](https://imagemagick.org/script/resources.php).
5. Separate versioned app files from proposed `%LOCALAPPDATA%\CWNG` state and user-selected library/ingest locations. Place databases/config/logs/cache/backups/migration markers explicitly. Audit current `CALIBRE_DBPATH` and Linux-specific plugin configuration. [Constants](https://github.com/dapih/Calibre-Web-NextGen/blob/f342724c25e82bbca580c04786154e0dd71c4811/cps/constants.py), [plugin helper](https://github.com/dapih/Calibre-Web-NextGen/blob/f342724c25e82bbca580c04786154e0dd71c4811/cps/services/calibre_user_plugins.py).
6. Test conflicting installed tools first on PATH, poisoned CWD/environment, concurrent desktop Calibre, standard-user permissions and non-ASCII/spaced/long paths. Capture process/module traces and filesystem/registry changes. Dependency isolation is not a security sandbox against the same user.

## Upgrade and release decisions

Proposed upgrades stop tray/server/workers orderly, back up state, replace a complete payload, validate, then switch versions. Define migration failure/recovery and downgrade policy: installer rollback does not undo database migrations. Uninstall retains libraries/ingest/state by default; explicit data removal is separate. Inno's [closing mechanism](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm) is only a primitive.

The [existing workflow](https://github.com/dapih/Calibre-Web-NextGen/blob/f342724c25e82bbca580c04786154e0dd71c4811/.github/workflows/docker-image-build-release.yml) signs/attests Linux OCI images, not Windows EXEs. A future Windows lane needs pinned tools/actions, locked hashes, SBOM/notices/source and final-artifact provenance. Hosted Windows runners are build hosts with preinstalled software, not clean Windows 11 acceptance machines. [Runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Owner decisions:

- Signing identity/budget: consider [SignPath Foundation](https://signpath.org/) (free OSS program, acceptance required), [Azure Artifact Signing](https://azure.microsoft.com/en-us/products/artifact-signing) (advertised USD 9.99/month/5,000 signatures, eligibility/identity/region restrictions), or CA/HSM-backed OV with a current quote. Name billing, custody, approval, recovery and revocation owners. [Microsoft options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options).
- Sign/verify final binaries, installer/uninstaller and relevant temporary setup copies with SHA-256/RFC3161 timestamp; keep third-party provenance. Inno's integrated signing covers copies that outer-EXE-only signing can miss. Signing CI may use the network; installation/runtime must not require it. [SignTool](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool), [Inno signing](https://jrsoftware.org/ishelp/topic_setup_signtool.htm).
- Windows uses Authenticode/trust checks, not Apple notarization. Signing does not guarantee immediate SmartScreen reputation; EV no longer bypasses it. Smart App Control can block unknown unsigned components, so test the entire payload. [Reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation), [Smart App Control](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/overview).
- Publish final EXE checksums, source/manifest and attestation. Attestation supplements Authenticode; optional offline verification also needs bundle/trusted-root material, not end-user installation of GitHub CLI. [Offline verification](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/verify-attestations-offline).

## Possible later feasibility gate

The architecture ticket owns candidate selection and explicit unexecuted gates. A possible later feasibility gate is to **prove isolated Windows x64 loading and local workflows**: resolve wheel gaps at build time; capture payload/import/process manifests; exercise native conversion, MIME, image/PDF and archive fixtures with zero host modifications. This describes potential evidence for later implementation authorization, not a new required implementation task in the planning map.

Later release gates:

1. Fresh standard-user Windows 11 x64 VM, no dev/Python/Calibre/ImageMagick installation, network disabled: install/start/restart/uninstall the single EXE.
2. Disconnected library/reader/ingest/conversion/local metadata/OPDS/plugin download, then LAN-only Kobo/KOReader checks. Explicit optional limitations (including LDAP/remote providers) must not conceal core failures.
3. Isolation conflict matrix passes; N→N+1, interrupted upgrade, failed migration, retained-state reinstall and unsupported downgrade preserve the agreed data policy.
4. Measured size/startup/temp-disk requirements fit one EXE; final hashes/signatures/source/notices match; trust checks cover downloaded-file/offline certificate conditions and chosen Windows security policies.

Remaining decisions: CPython variant/frozen fallback, per-user/machine scope, signing ownership, native payload/license selection, optional-feature limits and retention/downgrade policy. The architecture ticket should state which choices are provisional and which later evidence would confirm them.

Research used local pinned sources and official vendor/project documentation/license texts, accessed 2026-11-04.
